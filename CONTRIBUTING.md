# Contributing

Thanks for your interest in improving this project.

## Before You Start

- Read the README first to understand the current scope and constraints.
- Open an issue before large changes so the direction is aligned.
- Keep changes small, focused, and easy to review.

## Pull Requests

- Use a short-lived branch for each change.
- Explain what changed and why.
- Update docs when behavior, commands, or setup changes.
- Avoid unrelated refactors in the same pull request.

## Quality Bar

- Do not commit secrets, credentials, or private tokens.
- Do not make unsupported claims in docs or marketing copy.
- Preserve existing behavior unless the change explicitly intends to alter it.
- Add or update tests when the repository already has a testing setup and behavior changes.

## Reporting Issues

- Bug reports should include steps to reproduce, expected behavior, and actual behavior.
- Security issues should not be disclosed publicly before the maintainer has time to assess them.

## Review Expectations

Maintainers may request changes for safety, scope control, documentation quality, or consistency with the project direction.
