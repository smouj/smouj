## 🧭 Perfil

Desarrollador construyendo sistemas prácticos alrededor de **IA local**, **workflows de agentes**, **ingeniería de juegos** e **infraestructura en producción** — desplegados, testados, auditados y mejorados con el tiempo.

| Enfoque | |
|:---|:---|
| 🧠 **IA Local** | llama.cpp · GGUF · CUDA · Ollama · inferencia en GPU de consumo · APIs locales OpenAI-compatible |
| 🤖 **Workflows de Agentes** | identidades · skills · formatos de exportación · quality gates · archivos de herramientas específicos |
| 🎮 **Sistemas de Juego** | Recreaciones ROM-fieles · motores de combate GBC · sistemas de cartas · pipelines de pixel art |
| ⚙️ **Automatización** | agentes de navegador · workflows de código · scripts de validación · checks de infraestructura |

| Principio | |
|:---|:---|
| 🔍 Auditar primero | Inspeccionar el estado real antes de cambiar nada |
| 📦 Releases pequeñas y seguras | Cambios focalizados que se pueden testear y revertir |
| 🖥️ Local-first | La IA debería funcionar en hardware que la gente realmente posee |
| 🚦 Disciplina de producción | Logs, smoke tests, health checks, notas de rollback |
| 🏷️ Sin claims falsos | Experimental = etiquetado. Producción = validado |

## ⚙️ Workflow

| Paso | |
|:---|:---|
| 🔍 **01 · Auditar** | Inspeccionar el estado real antes de asumir el problema |
| 📐 **02 · Alcance** | Cambio más pequeño y seguro con rollback claro |
| 🔨 **03 · Implementar** | Cambios focalizados, radio de impacto limitado |
| ✅ **04 · Validar** | Lint · typecheck · tests · build · smoke |
| 📝 **05 · Documentar** | Qué cambió, por qué, cómo revertir |
| 🚀 **06 · Desplegar** | Deploy alineado con versión, health checks, verificación post-deploy |
